Future-product exploration · corrected v0.1.24 audit underneath

Three interaction languages—not three skins.

A · Living Paper makes content feel tangible. B · Quiet Ink makes functional UI nearly disappear. C · Context Thread visualizes the relationship between thought, place and time. The recommended hybrid deliberately uses different languages at different layers instead of forcing one metaphor across the whole product.

A · Living Paper

Best when the user is touching content: Skrib, media, reminder object, lightweight delight. Risk: scrapbook overload.

B · Quiet Ink

Best for shell, search, settings, recovery and dense reading. Risk: becoming too generic if used alone.

C · Context Thread

Best for Return, re-anchor, time continuity and context repair. Risk: abstract diagrams replacing normal UI.

Hybrid · Quiet Paper / Living Context

Precise shell + tactile thought + spatial continuity only where relationships genuinely matter.

At rest

B provides the calmest hierarchy; A gives the note its identity.

After intent

A can unfold content tools; B provides the clearest command mechanics.

When context changes

C earns its place through movement/relationship, not decoration.

When something fails

B should dominate. Error recovery must be boring, legible and trustworthy.

RECOMMENDED FOURTH DIRECTION

Quiet Paper / Living Context

Do not choose A, B or C globally. Use Quiet Ink as the functional base, Living Paper where users touch their own content, and Context Thread only when place/time relationships genuinely need explanation or continuity. That gives Skribli a recognisable identity without forcing every surface to perform the same metaphor.

Quiet InkHome · Find · Settings · search · controls · recovery · account
Living PaperSkrib · attachments · reminder object · colour/material · moments of delight
Context ThreadRail orientation · Return journey · re-anchor · context degradation · time continuity
