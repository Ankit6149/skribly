The widget and the bar are not the same thing.

The global desktop widget is always available and opens global Skribli access. The per-app bar belongs to the specific app/window where Skribs exist and opens only that context. The note is a separate mixed canvas. The Skribli app is the deeper library/control surface.

07 · Codex handoff

Build the separation before the decoration

The visual style only matters if each surface owns the correct behavior and lifecycle.

1 · Split the current rail responsibilities

Preserve valid data/open-context plumbing from `ContextRail.tsx`, but separate future Global Widget/Global Shelf from the new per-app Context Bar/Context Strip.

2 · Add target-following bar host

Create a transparent non-activating overlay tied to matching HWND geometry. It should only show when that context has Skribs and obey focus/monitor bounds.

3 · Refactor the note shell

Keep persistence/reminder/attachment domain logic. Replace crowded permanent controls with the polished mixed-canvas hierarchy shown above.

4 · Keep the main app deep

Library, Reminders, Settings and Account remain normal app-window destinations. They do not replace either desktop surface.

Current repo truth important

v0.1.24 currently has one global `ContextRail`; the per-app Context Bar described here is a new surface to build, not something to pretend already exists.

Technical reality Windows

“Inside the app” is perceptual. Do not inject UI into arbitrary third-party apps. Use a separate transparent overlay positioned from native window bounds.

Do not overbuild migration

Do not replace working storage, reminders, context capture or open-note lifecycle while redesigning presentation. Move incrementally and keep tests green.

CORRECTED FINAL CANDIDATE

Global Widget → Global Shelf. Per-app Bar → Context Strip.

Those are separate surfaces with separate scopes. The note is a polished mixed canvas, and the main Skribli app remains the deeper library/control room. This separation is now the handoff foundation.
