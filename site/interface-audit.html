Repository-grounded audit · 14 Sep 2026

Skribli has outgrown its first UI hierarchy.

The engineering has become substantially richer: rich text, ink, attachments, repeating reminders, tasks/archive, resizable note windows, context return, Here/All/Archive Rail scopes, local library, account enforcement and recovery. The UI problem is no longer missing capability. It is too much capability exposed too close to the same level.

THE CORE REDESIGN QUESTION
What is the smallest visible interface that makes the user's current intention obvious?

Anything else should remain one intentional gesture away. Skribli should feel like part of the user's existing work, not a second workplace.

Design contract

Ten rules before drawing another screen.

The redesign is structural first, visual second. A polished card grid would still be the wrong product.

Zero management tax

Context organizes by default. Users should not need folders, cleanup rituals, or daily archive maintenance.

Quiet until intention

Capabilities appear only after selection, gesture, focus, or explicit mode change.

Physical objects, precise shell

Skribs/media can feel tactile. Navigation, accessibility and layout remain exact.

Persistent UI must earn space

Rail, badges, notifications and widgets must be hideable, predictable and low-noise.

01
One visible intention per region

Writing should not visually compete with formatting, scheduling, lifecycle, resize and context management.

02
Context is felt before managed

Healthy context stays quiet. Confidence/re-anchor surfaces appear only when needed.

03
Feature ≠ toolbar button

Future arrows, labels, checklists and pins must extend a tool system, not widen a permanent strip.

04
Management lives elsewhere

Import/export, account, Trash, diagnostics and context rules leave the compact capture experience.

Too many peer actions critical

Draw, reminder/task, attachments, formatting, appearance and size do not deserve permanent equal weight.

Reminder and task semantics overlap critical

“Bring this thought back” and “this note is a completable task” need separate mental models.

Footer is lifecycle-heavy high

Save + Delete + Complete + Done makes leaving a thought feel like processing an item.

Resize is functionally strong, visually noisy high

Keep native hit zones and per-note geometry; hide decorative handles until pointer proximity.

Rich local capability is valuable keep

Do not remove capability. Build a semantic gateway: Add · Mark · Bring back, with contextual formatting and a secondary lifecycle menu.

Smallest components

The redesign includes atoms, not only screens.

Boxiness often starts here. When every atom becomes a rounded container, the whole product becomes a dashboard.

BUTTONOne dominant action per region

Use text/icon commands and spatial actions before filled pills everywhere.

TABOnly true peer modes

Lifecycle and context filters do not all deserve permanent tabs.

SEARCHUniversal retrieval primitive

Fast, keyboard-first, context-aware suggestions.

CONTEXT MARKHuman place, not window metadata

App mark + readable location; detail on demand.

COUNTUse only when decision-relevant

Persistent badges create attention debt.

POPOVERAttached to meaning

Tool tray/context sheet should feel connected to source, not another box.

CONFIRMATIONPrefer reversible state

Only irreversible delete should require strong confirmation.

FOCUSNever trade accessibility for softness

2px ink/olive focus ring survives paper textures and high contrast.

SCROLLQuiet until used

Subtle thumb, stable layout, explicit in forced-colours mode.

RESIZEInvisible hit zone + teaching cue

Native geometry without four permanent visual handles.

LOADINGPreserve spatial layout

Tiny ink/paper motion or progress copy; no spinner collection.

EMPTYWhitespace is a valid state

One sentence + one action, not an explanatory card.

Motion & input

Motion must explain continuity.

Pointer delight is valuable, but every interaction must survive keyboard, touch, stylus, scaling and reduced motion.

90–160 ms · Acknowledge

Hover, focus, selected tool, button feedback.

160–240 ms · Reveal

Tool gateway, attachment actions, Rail detail, contextual formatting.

220–360 ms · Recompose

Note expands for exact reminder/drawing; reading pane changes.

280–500 ms · Travel

Return to place, complete→Past, re-anchor. Reduced motion removes travel but keeps state continuity.

Recommended future IA

Daily, Find, Control.

Three layers keep capability without making users operate Skribli as a second productivity environment.

Daily layer

Almost invisible

Skribli appears inside the user's existing work.

  • Shortcut → Skrib
  • My Skribs presence / retrieval
  • Reminder notification
Find layer

Intentional retrieval

Open only when the user wants to look across thoughts.

  • Universal search
  • Context-aware results
  • Reading detail
  • Past/Trash filters
  • Reminder lens
Control layer

Occasional management

All low-frequency responsibility gets a real home.

  • Settings
  • Context & Privacy
  • Data & Recovery
  • Account
  • Updates / About
