# Side panel revision — 11 October 2026

Part of ARC-66. Executor: Codex. Status: concepts prepared; owner selection and runtime implementation remain open.

## Owner feedback

The previous panel concepts felt like buttons and boxes on a boxy website. Frosting and round corners did not resolve the repeated containment.

## Revised brief

Keep the full-height edge panel extending inward over the desktop with actual native frosted material as an implementation requirement. Preserve the Soft Paper Play identity, existing note content, local search, scope/app access, Archive/Restore, one reused editor and separate Open / Return actions. General notes have no Return action.

Reduce idle chrome: unboxed search and capture affordances, a single compact scope menu, no app-icon tiles, no pill-filter rows and no nested card shells. Focus the hierarchy on the person's note text; secondary provenance should identify where the thought belongs without becoming another button.

Three independent built-in Image Gen concepts are saved in `artifacts/frosted-panel-review-v2-20261011/`, numbered by displayed order: direct thoughts on frost; one focal paper leaf with a quiet supporting collection; a bounded arrangement of paper slips. These are conceptual alternatives, not installed app evidence.

## Review and limits

All five synthetic notes are present in each image, with readable previews and quieter controls. Image 2 omits a distinct Return action. Image 3 uses ambiguous action glyphs and omits the folded-note brand mark. Correct those in any selected prototype; icons alone must not obscure the Open / Return distinction. Supporting actions revealed on hover must also appear on keyboard focus, and all controls need discoverable accessible names. Decorative marks, textures and shape details are concepts, not production assets.

Actual blur, window geometry, both docking sides, reveal/hit-region clipping, focus restoration, DPI, reduced motion, forced colours, opaque fallback and performance require implementation and Windows acceptance. No production UI, native behavior, installer or publication changed in this revision. Prior public-release gates remain open.

The owner can select a direction or refine it further before implementation. The prior three concepts remain retained as superseded exploration.
